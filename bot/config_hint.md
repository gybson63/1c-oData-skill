## Важные особенности

- Поле «ФИО» у сотрудника и физлица: `Description`
- Сотрудник связан с физлицом через поле `ФизическоеЛицо_Key`
- Организация в документах — поле `Организация_Key`
- Подразделение в документах — поле `ПодразделениеОрганизации_Key`
- Дата приёма сотрудника хранится в Document_ПриемНаРаботу, а не в справочнике Сотрудники

## Типовые запросы (ЗУП)

### Сотрудники с должностью и подразделением (не GUID)
- Entity: `InformationRegister_КадроваяИсторияСотрудников/SliceLast()`
- Select: `Сотрудник_Key`, `Должность_Key`, `ПодразделениеОрганизации_Key` (или `Подразделение_Key` — зависит от ИБ)
- Expand: `Сотрудник,Должность,ПодразделениеОрганизации` — только если OData принимает $expand на entity
- Если `/SliceLast()` возвращает code 6 «лишние сегменты»: бот автоматически переключится на `InformationRegister_КадроваяИсторияСотрудников_RecordType` с `$orderby=Period desc` и dedupe по `Сотрудник_Key`

### Численность по подразделениям (таблица/analytics)
- mode=analytics, queries: SliceLast кадровой истории
- group_by: `ПодразделениеОрганизации_Key` (или Description после join)
- Не добавляй лишние сегменты к entity

### Кто сейчас в отпуске
- Entity: `Document_Отпуск` или регистр отсутствий (не Catalog_Сотрудники/DeletionMark)
- Filter по периоду отпуска: `ДатаНачала`, `ДатаОкончания` — поля документа отпуска

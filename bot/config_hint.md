## Важные особенности

- Поле «ФИО» у сотрудника и физлица: `Description`
- Сотрудник связан с физлицом через поле `ФизическоеЛицо_Key`
- Организация в документах — поле `Организация_Key`
- Подразделение в документах — в конфигурации часто `ПодразделениеОрганизации`, в OData публикации может быть `Подразделение_Key` / nav `Подразделение` — **всегда проверяй get_entity_fields**
- Дата приёма сотрудника хранится в Document_ПриемНаРаботу, а не в справочнике Сотрудники

## Типовые запросы (ЗУП)

### Сотрудники с должностью и подразделением (не GUID)
- Entity: `InformationRegister_КадроваяИсторияСотрудников/SliceLast()`
- Select: `Сотрудник_Key`, `Должность_Key`, и поле подразделения из метаданных (`Подразделение_Key` или `ПодразделениеОрганизации_Key`)
- Expand: `Сотрудник,Должность` + nav подразделения из метаданных (`Подразделение` или `ПодразделениеОрганизации`) — только если OData принимает $expand
- Если `/SliceLast()` возвращает code 6 «лишние сегменты»: бот автоматически переключится на `InformationRegister_КадроваяИсторияСотрудников_RecordType` с `$orderby=Period desc` и dedupe по `Сотрудник_Key`

### Численность по подразделениям (таблица/analytics)
- mode=analytics, queries: SliceLast кадровой истории
- group_by: `ПодразделениеОрганизации_Key` (или Description после join)
- Не добавляй лишние сегменты к entity

### Кто сейчас в отпуске
- Entity: `Document_Отпуск` или регистр отсутствий (не Catalog_Сотрудники/DeletionMark)
- Filter по периоду отпуска: `ДатаНачала`, `ДатаОкончания` — поля документа отпуска

### Остатки отпусков (сколько дней осталось)
- **Модель:** остаток = накоплено − израсходовано (не одно поле в `Document_Отпуск`).
- **Готовый остаток в днях (предпочтительно):** `InformationRegister_АналитикаОстатковОтпусков`
  - Select: `Сотрудник_Key`, `ВидЕжегодногоОтпуска_Key`, `Дата`, `ОстатокДней`
  - Orderby: `Дата desc` — запрос к **шапке** IR (не `_RecordType`; для этого регистра `_RecordType` часто 404)
- **Расходная нога (израсходовано):** `AccumulationRegister_ФактическиеОтпуска/Turnovers()` — движения от `Document_Отпуск` и др.; поле `КоличествоTurnover`. На `zup_gazaliev` `/Balance()` **не опубликован** → используй `/Turnovers()` или `_RecordType`
- **Ввод / начислено:** `InformationRegister_НачальныеОстаткиОтпусков_RecordType` (`КоличествоДней`, `ДатаОстатка`), `InformationRegister_ПоложенныеВидыЕжегодныхОтпусков_RecordType` (`КоличествоДнейВГод`) — только часть формулы, не «текущий остаток» сами по себе
- **Не путать:** `Document_Отпуск` — оформление отпуска (расход), не таблица остатков; `InformationRegister_ОстаткиОтпусков` в OData **нет** (404)
- **AccumulationRegister:** сначала виртуальная таблица из metadata (`/Balance()`, `/Turnovers()`, `/BalanceAndTurnovers()`); не выдумывай `КоличествоBalance`
- **InformationRegister без VT:** поля среза — через `_RecordType`, не через шапку регистра
- Поле вида отпуска в OData: `ВидЕжегодногоОтпуска_Key` (не `ВидОтпуска_Key` без проверки metadata)

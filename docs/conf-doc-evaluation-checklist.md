# Чеклист оценки пользы MCP 1c-conf-doc (ЗУП 3.1)

Сравнение **с conf-doc** и **без conf-doc** на одной и той же базе OData.

Конфигурация в индексе: `ЗарплатаИУправлениеПерсоналомКОРП` (9910 объектов).

---

## Подготовка

### Вариант A — Cursor (агент)

| Режим | Действие |
|-------|----------|
| **С conf-doc** | Оба MCP в [`.cursor/mcp.json`](../.cursor/mcp.json): `1c-odata` + `1c-conf-doc`, backend на `:8050` |
| **Без conf-doc** | Временно отключить сервер `1c-conf-doc` в MCP Settings (оставить только `1c-odata`) |

После смены конфигурации — перезапуск Cursor.

### Вариант B — Telegram / email-бот

| Режим | Действие |
|-------|----------|
| **С conf-doc** | В `env.json` → `agents.odata.conf_doc.enabled: true` |
| **Без conf-doc** | `conf_doc.enabled: false` (перезапуск бота) |

В логах при включённом conf-doc должно появляться:
`conf_doc: enriched prompt with N results`

### Что фиксировать по каждому вопросу

| Критерий | Оценка |
|----------|--------|
| **entity** с первой попытки верный? | да / нет |
| **filter/select** по смыслу запроса корректны? | да / частично / нет |
| Агент **вызвал conf-doc** (`conf_doc_search` / `get_object`)? | да / нет / н/д |
| Ответ **без ошибки** OData (code 8, 404 entity)? | да / нет |
| **Время** до ответа (грубо) | ~сек |

Итоговая шкала на вопрос: **+2** отлично · **+1** с доработкой · **0** без разницы · **−1** хуже с conf-doc.

## Блок 1 — Структура конфигурации (conf-doc должен сильно помочь)

Эти вопросы **не требуют данных из базы** — проверяют понимание метаданных.

### 1. Реквизиты документа отпуска

**Вопрос:** «Какие основные реквизиты у документа Отпуск в ЗУП?»

| | Ожидание |
|---|----------|
| conf-doc | `conf_doc_search` → `Document.Отпуск` → chunk с реквизитами (Сотрудник, период, вид отпуска и т.д.) |
| Без conf-doc | Часто общий ответ или угадывание; `$metadata` даёт поля только если `Document_Отпуск` опубликован в OData |

**Эталон OData (если опубликован):** `Document_Отпуск`

---

### 2. Отпуск vs отпуска сотрудников

**Вопрос:** «Чем документ Отпуск отличается от ОтпускаСотрудников?»

| | Ожидание |
|---|----------|
| conf-doc | Находит оба: `Document.Отпуск`, `Document.ОтпускаСотрудников`, читает справку/реквизиты |
| Без conf-doc | Путает объекты или описывает только один |

---

### 3. Средний заработок — какой объект?

**Вопрос:** «В каком объекте конфигурации хранится расчёт среднего заработка для отпуска?»

| | Ожидание conf-doc (примеры из search) |
|---|--------------------------------------|
| Кандидаты | `Document.СреднийЗаработокСЭДО`, регистры/показатели расчёта, формы анализа |
| Без conf-doc | `search_entities('средний')` часто **пусто** — в имени OData-сущности нет подстроки |

---

### 4. Табель — поля для фильтра по периоду

**Вопрос:** «Какие реквизиты у документа Табель учёта рабочего времени для фильтрации по месяцу?»

| | Ожидание |
|---|----------|
| conf-doc | `Document.ТабельУчетаРабочегоВремени` + список реквизитов |
| OData | `Document_ТабельУчетаРабочегоВремени` |

---

### 5. Увольнение — связанные объекты

**Вопрос:** «Какие документы и регистры связаны с увольнением сотрудника?»

| | Ожидание |
|---|----------|
| conf-doc | `Document.Увольнение` (score ~0.97), `Document.УвольнениеСписком`, отчёт `ПричиныУвольнения` |
| Без conf-doc | Только `Document_Увольнение` если опубликован; связи не видны |

## Блок 2 — Данные через OData (conf-doc помогает выбрать entity и поля)

Нужна **опубликованная** OData-база с тестовыми данными. Подставьте реальные ФИО / период из вашей ИБ.

### 6. Список сотрудников (ФИО, должность, подразделение)

**Вопрос:** «Покажи 10 штатных сотрудников: ФИО, должность и подразделение»

| | Ожидание |
|---|----------|
| Империка / hint | Текущее состояние — **не** справочник: `InformationRegister_КадроваяИсторияСотрудников/SliceLast()` (fallback `_RecordType` на `zup_gazaliev`) |
| conf-doc | `InformationRegister.КадроваяИсторияСотрудников` — измерения (`Сотрудник`), ресурсы (`Подразделение`, `Должность`); `Catalog.Сотрудники` только для ФИО |
| OData | `InformationRegister_КадроваяИсторияСотрудников/SliceLast()` → при code 6 `_RecordType` + `$orderby=Period desc`; lookup `Catalog_Сотрудники` для `Description` |
| Без conf-doc | Часто уход в `mode=analytics` с невалидным join или неверный entity |

*После индексации регистров в conf-doc (2026-06-08): conf-doc помогает выбрать IR вместо `Catalog_Сотрудники`.*

---

### 7. Отпуска за период

**Вопрос:** «Покажи отпуска сотрудников за май 2025: сотрудник, даты, вид отпуска»

| | Ожидание |
|---|----------|
| conf-doc | `Document.Отпуск` или `Document.ОтпускаСотрудников` + реквизиты для `$filter` по дате |
| OData | `Document_Отпуск` / `Document_ОтпускаСотрудников` + корректный filter по полю даты |
| Типичная ошибка без conf-doc | Неверный документ или фильтр по `Date` вместо реквизита периода отпуска |

---

### 8. Остатки отпусков

**Вопрос (блок 2):** «Сколько дней отпуска осталось у сотрудников?»

| | Ожидание |
|---|----------|
| Модель | **Остаток = накоплено − израсходовано** |
| conf-doc | `АналитикаОстатковОтпусков`, `НачальныеОстаткиОтпусков`, `ФактическиеОтпуска` |
| OData (primary) | `InformationRegister_АналитикаОстатковОтпусков` → `ОстатокДней` |
| OData (расход) | `AccumulationRegister_ФактическиеОтпуска/Turnovers()` — `/Balance()` на `zup_gazaliev` **нет** |
| Статус | **+2 / +2** в `diag_block2_q8.py` (2026-06-07); [case-n8-vacation-balance.md](case-n8-vacation-balance.md) |

**Диагностика:** `python scripts/diag_block2_q8.py` · **probe:** `python scripts/probe_vacation_balance.py`

---

### 9. Начисления / ведомость

**Вопрос:** «Покажи начисления зарплаты за апрель 2025 по организации X»

| | Ожидание |
|---|----------|
| conf-doc | Документы начисления, `Document.ВедомостьНаВыплатуЗарплатыВБанк`, регистры расчёта |
| OData | Зависит от публикации; часто `Document_*` + регистр `CalculationRegister_*` / `AccumulationRegister_*` |

---

### 10. Увольнения за год

**Вопрос:** «Сколько увольнений было в 2024 году?»

| | Ожидание |
|---|----------|
| conf-doc | `Document.Увольнение` → поля даты для `$filter` |
| OData | `Document_Увольнение?$filter=...&$count=true` или `count:true` в боте |
| Без conf-doc | Часто верный entity; выигрыш conf-doc — правильное поле даты и `DeletionMark` |

**Интерпретация суммы Δ:**
- **+8 и выше** — conf-doc даёт существенный выигрыш, оставлять включённым

- **0 … +2** — в основном дублирует `$metadata`; имеет смысл только в Cursor для справки
- **отрицательный** — замедляет или путает; проверить `search_top_k`, качество индекса

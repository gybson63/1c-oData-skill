# Внешняя обработка: Включение интерфейса OData

## Назначение

Обработка позволяет выбрать конкретные объекты конфигурации для публикации через OData — без Конфигуратора, прямо из режима Предприятия.

## Структура файлов

```
EnableODataInterface/
  EnableODataInterface.xml          — метаданные обработки
  Forms/
    MainForm/
      Ext/
        Form.xml                    — структура формы
        Form/
          Module.bsl                — модуль формы (вся логика здесь)
```

При открытии обработка читает текущий состав OData и расставляет флажки. При нажатии **«Применить»** — сохраняет только отмеченные объекты.

## Как собрать EPF

Через скрипт из репозитория cc-1c-skills:

```powershell
powershell.exe -NoProfile -File .claude/skills/epf-build/scripts/epf-build.ps1 `
    -SourceFile "processing/EnableODataInterface.xml" `
    -OutputFile "processing/EnableODataInterface.epf"
```

Если база занята конфигуратором — скрипт автоматически создаст временную базу-заглушку.

Или вручную через 1С Конфигуратор: Файл → Загрузить внешнюю обработку из XML → выбрать `EnableODataInterface.xml`.

## Использование

1. Откройте обработку в 1С: Файл → Открыть → `EnableODataInterface.epf`
2. Отметьте нужные объекты по типам
3. Нажмите **«Применить»**
4. Дождитесь сообщения об успешной публикации

## Требования

- 1С:Предприятие 8.3.6+
- Права администратора в информационной базе
- База опубликована на веб-сервере с включённым OData

## Логика обновления состава

При открытии обработка вызывает `ПолучитьСоставСтандартногоИнтерфейсаOData()` и проставляет флажки по типам — отмечены те, которые уже опубликованы.

При нажатии **«Применить»** обработка применяет следующие правила:

| Флажок | Поведение |
|--------|-----------|
| ☑ Включён | Все объекты этого типа будут опубликованы |
| ☐ Снят | Все объекты этого типа будут убраны из OData |
| Тип не показан в форме (напр. ПланыОбмена) | Сохраняется текущее состояние без изменений |

## Замечание о производительности

Для больших конфигураций (500+ объектов) первое обращение к OData после публикации может быть медленным — сервер строит метаданные.
